# API Reference

All services expose JSON over HTTP. Interactive documentation is generated by springdoc. Every endpoint documents its request body, response schemas, status codes and validation rules, with realistic example payloads you can run with **Try it out**.

| Service | Base URL | Swagger UI | OpenAPI JSON | OpenAPI YAML |
|---|---|---|---|---|
| Agent | `http://localhost:8080` | http://localhost:8080/swagger-ui.html | http://localhost:8080/v3/api-docs | http://localhost:8080/v3/api-docs.yaml |
| Orders | `http://localhost:8081` | http://localhost:8081/swagger-ui.html | http://localhost:8081/v3/api-docs | http://localhost:8081/v3/api-docs.yaml |
| Inventory | `http://localhost:8082` | http://localhost:8082/swagger-ui.html | http://localhost:8082/v3/api-docs | http://localhost:8082/v3/api-docs.yaml |
| Payments | `http://localhost:8083` | http://localhost:8083/swagger-ui.html | http://localhost:8083/v3/api-docs | http://localhost:8083/v3/api-docs.yaml |
| CRM | `http://localhost:8084` | http://localhost:8084/swagger-ui.html | http://localhost:8084/v3/api-docs | http://localhost:8084/v3/api-docs.yaml |
| Delivery | `http://localhost:8085` | http://localhost:8085/swagger-ui.html | http://localhost:8085/v3/api-docs | http://localhost:8085/v3/api-docs.yaml |

Ports follow the `*_PORT` environment variables; the "Servers" entry in Swagger UI always reflects the host you opened it from. Field examples, validation constraints and the shared error schema come from `commerce-common`, so they are identical in every service.

Health: `GET /actuator/health` on every service. The agent also exposes `GET /actuator/circuitbreakers`.

## Conventions

### Pagination

List endpoints accept `page` (zero-based, default 0) and `size` (default 20, maximum 100; out-of-range values are clamped, not rejected). Results are sorted by `id`.

```json
{
  "content": [ { "id": 1 } ],
  "page": 0,
  "size": 20,
  "totalElements": 1,
  "totalPages": 1
}
```

### Error format

Every error uses the same body:

```json
{
  "timestamp": "2026-10-13T05:00:00.123Z",
  "status": 404,
  "code": "NOT_FOUND",
  "message": "Order 99 was not found",
  "details": []
}
```

| `code` | HTTP status | Meaning |
|---|---|---|
| `VALIDATION_FAILED` | 400 | Bad body, parameter or malformed JSON; `details` lists `field: message` |
| `NOT_FOUND` | 404 | Resource does not exist |
| `BUSINESS_RULE_VIOLATION` | 409 | Illegal state change, insufficient stock, payment mismatch, and similar |
| `DELIVERY_DELAYED` | 503 | Shipment cannot leave the origin warehouse (severe weather) |
| `UPSTREAM_UNAVAILABLE` | 503 | A downstream service or its circuit breaker is unavailable |
| `INTERNAL_ERROR` | 500 | Unexpected failure |

The exact `message` text is illustrative; clients should branch on `code`.

## Checkout Agent (`:8080`, `/api/v1/agent`)

### `POST /checkouts`

Places an order and runs the whole flow: order, stock reservation, payment, shipment, and autonomous re-routing if delivery is delayed.

| Field | Type | Rules |
|---|---|---|
| `customerId` | number | required |
| `destination` | string | required, not blank |
| `paymentMethod` | `CARD`, `PAYPAL`, `WALLET` | required |
| `items[]` | array | required, at least one |
| `items[].sku` | string | required |
| `items[].quantity` | integer | at least 1 |
| `items[].unitPrice` | decimal | at least 0.01 |

Request:

```json
{
  "customerId": 1,
  "destination": "12 High St, Leeds",
  "paymentMethod": "CARD",
  "items": [ { "sku": "SKU-100", "quantity": 2, "unitPrice": 19.99 } ]
}
```

Outcomes:

| `outcome` | HTTP | Meaning |
|---|---|---|
| `COMPLETED` | 201 | Shipped from the primary warehouse |
| `REROUTED` | 201 | Primary was delayed; shipped from another warehouse |
| `DELIVERY_DELAYED` | 202 | No warehouse can ship now; order is paid and waiting |
| `PAYMENT_DECLINED` | 402 | Payment declined; reservation released, order cancelled |
| `OUT_OF_STOCK` | 409 | No warehouse has the stock; order cancelled |

Response, normal weather (`201`):

```json
{
  "order": {
    "id": 1, "customerId": 1, "destination": "12 High St, Leeds",
    "status": "SHIPPED", "warehouseId": 1, "total": 39.98,
    "items": [ { "sku": "SKU-100", "quantity": 2, "unitPrice": 19.99 } ],
    "createdAt": "2026-10-13T05:00:00Z"
  },
  "outcome": "COMPLETED",
  "fulfilledFrom": { "id": 1, "code": "LON", "name": "London Central", "region": "SOUTH_ENGLAND", "priority": 1 },
  "trackingCode": "TRK-3F9A1C2B",
  "timeline": [
    "Order 1 created",
    "Stock reserved at LON",
    "Payment authorised",
    "Shipment booked from LON, tracking TRK-3F9A1C2B"
  ]
}
```

Response, severe weather in `SOUTH_ENGLAND` (`201`, re-routed):

```json
{
  "order": { "id": 2, "status": "SHIPPED", "warehouseId": 2, "total": 39.98 },
  "outcome": "REROUTED",
  "fulfilledFrom": { "id": 2, "code": "MAN", "name": "Manchester Hub", "region": "NORTH_ENGLAND", "priority": 2 },
  "trackingCode": "TRK-7B20D4E1",
  "timeline": [
    "Order 2 created",
    "Stock reserved at LON",
    "Payment authorised",
    "Delivery from LON delayed: Severe weather in SOUTH_ENGLAND: shipments cannot leave warehouse 1",
    "Agent (priority-rule) selected warehouse MAN in NORTH_ENGLAND",
    "Shipment booked from MAN, tracking TRK-7B20D4E1"
  ]
}
```

`order` is shortened here; the full object has the same fields as the first example. With Gemini enabled the timeline line reads `Agent (gemini) selected ...`.

Response, no alternative available (`202`):

```json
{
  "order": { "id": 3, "status": "DELIVERY_DELAYED", "warehouseId": 1 },
  "outcome": "DELIVERY_DELAYED",
  "fulfilledFrom": { "id": 1, "code": "LON", "region": "SOUTH_ENGLAND", "priority": 1 },
  "trackingCode": null,
  "timeline": [
    "Order 3 created",
    "Stock reserved at LON",
    "Payment authorised",
    "Delivery from LON delayed: Severe weather in SOUTH_ENGLAND: shipments cannot leave warehouse 1",
    "No alternative warehouse can fulfil the order"
  ]
}
```

Response, payment declined (`402`, amount above `PAYMENT_MAX_AMOUNT`):

```json
{
  "order": { "id": 4, "status": "CANCELLED" },
  "outcome": "PAYMENT_DECLINED",
  "fulfilledFrom": null,
  "trackingCode": null,
  "timeline": [ "Order 4 created", "Stock reserved at LON", "Order cancelled: payment was declined" ]
}
```

Response, out of stock (`409`):

```json
{
  "order": { "id": 5, "status": "CANCELLED" },
  "outcome": "OUT_OF_STOCK",
  "fulfilledFrom": null,
  "trackingCode": null,
  "timeline": [ "Order 5 created", "Order cancelled: no warehouse has the requested stock" ]
}
```

Validation failure (`400`):

```json
{
  "timestamp": "2026-10-13T05:00:00Z", "status": 400, "code": "VALIDATION_FAILED",
  "message": "Request validation failed",
  "details": [ "items: must not be empty", "destination: must not be blank" ]
}
```

## Orders (`:8081`, `/api/v1/orders`)

| Method | Path | Description | Success |
|---|---|---|---|
| POST | `/` | Create an order | 201 |
| GET | `/{id}` | Get an order (cached) | 200 |
| GET | `/?page=&size=` | List orders, paged | 200 |
| PATCH | `/{id}/status` | Change status | 200 |

Create request:

```json
{
  "customerId": 1,
  "destination": "12 High St, Leeds",
  "items": [ { "sku": "SKU-100", "quantity": 2, "unitPrice": 19.99 } ]
}
```

Create response (`201`):

```json
{
  "id": 1, "customerId": 1, "destination": "12 High St, Leeds",
  "status": "CREATED", "warehouseId": null, "total": 39.98,
  "items": [ { "sku": "SKU-100", "quantity": 2, "unitPrice": 19.99 } ],
  "createdAt": "2026-10-13T05:00:00Z"
}
```

Status update request (`warehouseId` optional):

```json
{ "status": "PAID", "warehouseId": 1 }
```

Allowed transitions:

| From | To |
|---|---|
| `CREATED` | `PAID`, `CANCELLED` |
| `PAID` | `SHIPPED`, `DELIVERY_DELAYED`, `CANCELLED` |
| `DELIVERY_DELAYED` | `REROUTED`, `SHIPPED`, `CANCELLED` |
| `REROUTED` | `SHIPPED`, `DELIVERY_DELAYED` |
| `SHIPPED`, `CANCELLED` | none |

An illegal change returns `409 BUSINESS_RULE_VIOLATION`.

## Inventory (`:8082`, `/api/v1/inventory`)

| Method | Path | Description | Success |
|---|---|---|---|
| GET | `/warehouses?page=&size=` | List warehouses, paged | 200 |
| POST | `/availability` | Warehouses that can fulfil a basket (cached) | 200 |
| PUT | `/warehouses/{warehouseId}/stock` | Set a SKU's stock level | 204 |
| POST | `/reservations` | Reserve stock for an order | 201 |
| DELETE | `/reservations/{orderId}` | Release the order's reservation | 200 |

Seed data (disable with `INVENTORY_SEED_ENABLED=false`):

| Code | Region | Priority | SKU-100 | SKU-200 |
|---|---|---|---|---|
| LON | SOUTH_ENGLAND | 1 | 50 | 30 |
| MAN | NORTH_ENGLAND | 2 | 40 | 20 |
| BHX | MIDLANDS | 3 | 25 | 10 |

Availability request (`excludedRegions` optional):

```json
{ "items": [ { "sku": "SKU-100", "quantity": 2 } ], "excludedRegions": ["SOUTH_ENGLAND"] }
```

Availability response (`200`), ordered by priority:

```json
[
  { "id": 2, "code": "MAN", "name": "Manchester Hub", "region": "NORTH_ENGLAND", "priority": 2 },
  { "id": 3, "code": "BHX", "name": "Birmingham Depot", "region": "MIDLANDS", "priority": 3 }
]
```

Set stock request:

```json
{ "sku": "SKU-100", "quantity": 100 }
```

Reserve request / response (`201`):

```json
{ "orderId": 1, "warehouseId": 1, "items": [ { "sku": "SKU-100", "quantity": 2 } ] }
```

```json
{ "orderId": 1, "warehouseId": 1, "status": "RESERVED" }
```

Release response (`200`): `{ "orderId": 1, "warehouseId": 1, "status": "RELEASED" }`.

The availability cache is cleared whenever stock is set, reserved or released, and entries also expire after `CACHE_TTL`.

## Payments (`:8083`, `/api/v1/payments`)

| Method | Path | Description | Success |
|---|---|---|---|
| POST | `/` | Pay for an order, idempotent per `orderId` | 201 |
| GET | `/{id}` | Get a payment (cached) | 200 |
| GET | `/?page=&size=` | List payments, paged | 200 |

Request:

```json
{ "orderId": 1, "amount": 39.98, "method": "CARD" }
```

Response (`201`):

```json
{ "id": 1, "orderId": 1, "amount": 39.98, "method": "CARD", "status": "AUTHORIZED", "createdAt": "2026-10-13T05:00:00Z" }
```

`status` is `DECLINED` when `amount` exceeds `PAYMENT_MAX_AMOUNT` (default 10000). Repeating the same request returns the existing payment; a retry for the same order with different details returns `409 BUSINESS_RULE_VIOLATION`.

## Delivery (`:8085`, `/api/v1`)

| Method | Path | Description | Success |
|---|---|---|---|
| POST | `/shipments` | Book a shipment | 201 |
| GET | `/shipments/{id}` | Get a shipment (cached) | 200 |
| GET | `/shipments?page=&size=` | List shipments, paged | 200 |
| GET | `/delivery/weather` | Current weather restrictions | 200 |
| PUT | `/delivery/weather` | Update restrictions (simulated feed) | 200 |

Book request:

```json
{ "orderId": 1, "warehouseId": 2, "warehouseRegion": "NORTH_ENGLAND", "destination": "12 High St, Leeds" }
```

Book response (`201`):

```json
{
  "id": 1, "orderId": 1, "warehouseId": 2, "warehouseRegion": "NORTH_ENGLAND",
  "destination": "12 High St, Leeds", "status": "SCHEDULED",
  "trackingCode": "TRK-7B20D4E1", "createdAt": "2026-10-13T05:00:00Z"
}
```

Book response when the origin region is affected (`503`):

```json
{
  "timestamp": "2026-10-13T05:00:00Z", "status": 503, "code": "DELIVERY_DELAYED",
  "message": "Severe weather in SOUTH_ENGLAND: shipments cannot leave warehouse 1",
  "details": []
}
```

Weather request / response:

```json
{ "severe": true, "affectedRegions": ["SOUTH_ENGLAND"] }
```

The same shape is returned by `GET /delivery/weather`. The initial state comes from `WEATHER_SEVERE` and `WEATHER_AFFECTED_REGIONS`.
